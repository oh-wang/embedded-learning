# 嵌入式学习 · Day 1｜从环形缓冲区退回，先补 C 语法

今天本来是要写一个环形缓冲区的，计划里把它排在阶段一第一周。我照着提示往下看，发现自己连 printf 怎么打印一个变量都拿不准，干脆停下来，先补语法。

摸底的时候被问「打印变量怎么写」，我写了 `printf("age")`。现在回头看这个错误挺典型：我以为把变量名放进引号里就能把它打印出来，实际上引号里的东西会被原样输出，程序只会打出 age 这三个字母，跟变量一点关系都没有。后面写 sensor.c 的时候我又犯了同一个毛病——变量声明好了，printf 里却把 25、60、0 直接写死在引号里，编译器直接给了三条「unused variable」告警，等于当面告诉我这几个变量白声明了。正确的写法是模板里用 %d 留坑，变量名写在引号外面，有几个坑就按顺序跟几个变量。

if 也踩了坑。想判断相等，我写成了 `if age = 20{ }`，圆括号没加，等号少写了一个，花括号前面还多加了分号。一个等号是赋值、两个等号才是判断相等，这个课上听过，但真动手写的时候还是顺出来了老习惯。而且写成赋值时编译器不一定报错，条件会变成恒成立，分支永远都进去——这种「能编译但逻辑错」的坑比编译不过更危险。

今天最有意思的是亲眼看到两件事。一是 printf 不像我以为的那样会自动换行，得自己写 \n；二是我把 %d 换成 %c 去打印 25，屏幕上几乎什么都看不见——因为 %c 会去拿 ASCII 码表里编号 25 的那个字符，那是个不可见的控制符。亲眼跑一次，比看十遍书都记得住。

修完 sensor.c 之后，编译结果是 0 error 0 warning，运行时三行输出整整齐齐。这是我第一次自己把一个程序从报错改到干净，感觉比一路顺着写下来踏实。

**今天主要学了**

- printf 的参数结构：模板写在引号里、变量写在引号外，格式符 %d 和变量按顺序一一对应
- if 的正确写法：条件加圆括号、判断相等用 ==、花括号前不加分号
- uint8_t 需要 #include <stdint.h>，以及「编译告警不是噪音，它真的能替你看出概念漏洞」
